## What shipped

**Fourteen language backends, taking the engine from nine to twenty-three.**
Wave 1 complete — Python, C#, Go, Rust, PHP, Ruby, Kotlin, Swift, Dart,
Scala — and four of wave 2: Haskell, Elixir, Erlang, OCaml.

Each one has a backend, a spec, a grammar in the release script, a row in
`README.md`'s language table, and an entry in
`docs/ROADMAP/IDEAS/MULTILANG.md` recording what it cost and what it taught.

**The single most useful thing to carry forward:** every one of the fourteen
was measured against a real repository, and **every measurement changed
something**. Not one exception. Go's test functions inflated the public API
two and a half times; Rust's workspace crates would have resolved one
member's import to another member's file; C#'s `#if` blocks hid ten
functions; Python's typed splats vanished from every annotated signature;
OCaml documented *below* its declarations and the first version found 0 of
50. Fixtures caught the rest. **A backend that has not been run against
somebody else's code is not finished.**

Also shipped, outside the languages:

- **Assembly** (the ninth backend, before the fourteen) — the first with no
  tree-sitter grammar, by design.
- **Doc coverage per language**, which immediately exposed that the measure
  was unfair to languages with no per-parameter convention, and the
  `param_docs` contract field that fixed it.
- **`Project → Check exactly`** in the app — the answer the staleness mark
  only approximates.
- **Sort by "least recently generated"**, the question staleness cannot ask.
- **The placeholder and context-note translations**, plus structural tests
  that stop the next literal getting in.
- **`docs/USAGE.md` rewritten** from an inventory of the code, and
  `documentation.nvim`'s README given the `## Languages` section it never had.

## Where to continue — the ranked list

**1. `documentation.nvim`'s remaining docs (`§10.7`).** The README is done;
`docs/` as a folder is not. `FEATURES/` is the nearest thing to an inventory
and is itself incomplete. Same method that worked for `USAGE.md`: inventory
from the code first, then close the gap. **This is the highest-value open
item** — twenty-three backends shipped and the docs folder describes a
smaller tool than exists.

**2. The parity pass (`§12`).** One row per contract capability, one column
per language, every empty cell filled or given a written reason naming what
in the language makes it impossible. Two inputs already exist:
`param_docs = false` on eight languages, and the fact that seven needed the
interface default separately. **The reasons matter as much as the fills** —
assembly has no parameter list because a label has no calling convention,
and that is a filled-in cell, not a gap.

**3. Per-project settings (`docmap-desktop`, carried over).** Languages
on/off and excluded paths. With twenty-three backends this went from nice to
load-bearing: a monorepo now matches far more extensions than it used to.

**4. The `BUG:` marker question.** Whether it should reach `check.lua` and
Quicks. The entry says a verdict that counts to-dos as defects needs its own
argument, and it still has none.

**Not scheduled:** the remaining sixteen languages. See the decisions below.

## Decisions taken that the next session must not re-litigate

Recorded in full in `documentation.nvim`'s
`docs/ROADMAP/IDEAS/MULTILANG.md` § *Four decisions taken 2026-08-20*.

1. **Coverage per language reports two counts.** `summarised` (comparable
   across all twenty-three) and `documented` (comparable across the fifteen
   that judge parameters). One figure per language would mix two measures.
2. **The interface default stays written out per backend.** Seven languages,
   seven explicit rules. A shared contract field was considered and declined
   — each language spells it differently and each has a different
   surrounding default.
3. **The interface-file question is answered per language.** OCaml's sibling
   `.mli`, C's per-file rule, Delphi's in-file split. They look alike and are
   not.
4. **Wave 4 is cancelled** — Fortran, Ada, COBOL, Delphi, MATLAB, VB.NET are
   not being built, and the rest of wave 2 plus waves 3 and 5 are *available*
   rather than scheduled. Scope, not difficulty. **They become buildable
   again the moment a user asks for one**, and the recorded decisions mean
   restarting costs a day rather than a rediscovery.

The standing instruction all four were decided under, worth keeping:
**rather more effort, correct and separable, than a shortcut that falls over
later.**

## Ideas recorded, nothing built

Four, each written where the plugin that owns it will look:

- **API traffic as a measurement** — `runtime-analysis.nvim` `IDEAS.md`
  §1.7b. Sizes, durations, retries-to-success and error taxonomy, in both
  directions. Metadata and shapes, **never payloads**, decided up front
  because the captures are committed. This is the step from counting to
  measuring, and the path to a profiler.
- **Compiler Explorer, two steps further** — `documentation.nvim` `IDEAS.md`
  §3.6. Compare two marked functions side by side in one `clientstate`, and
  offer a *local* Compiler Explorer. The committed page must never hard-code
  one machine's `localhost`.
- **Name the tool a missing panel needs** — `documentation.nvim` `IDEAS.md`
  §6.8. With one correction that matters: **the map's twenty checks are its
  own and need no linter in any language.** Only the Types panel is
  tool-dependent. A mason.nvim hint belongs in Neovim only.
- **User-supplied checklists, applied by an agent** — `documentation.nvim`
  `IDEAS.md` §6.9. Scoped to a language or to every project, run as a
  **report first**, applied only on a reader's choice, with an agent writing
  diffs through the MCP tools that already exist.

## How to run everything

```bash
nvim --headless -l scripts/ci.lua
```

in `documentation.nvim` — five gates. A docs change makes the map stale;
regenerate with `scripts/gen_map.lua` and commit the result.

The language specs skip when their grammar is absent, which is the normal
local state. To run them for real, point at the built grammars:

```bash
DOCMAP_PYTHON_PARSER=C:/tools/docmap-grammars/python.dll nvim --headless -u NONE -l TESTS/run.lua
```

Every backend spec reads its own `DOCMAP_<LANG>_PARSER`. All twenty-three
grammars are built into `C:/tools/docmap-grammars/` on this machine, and
`scripts/build_engine_release.sh` builds them from source for a release —
**twenty-three files for twenty-two languages**, because OCaml needs two
(`.ml` and `.mli` are different languages to the parser) and assembly needs
none.

In `docmap-desktop`:

```bash
cd src-tauri && cargo test
```

```bash
node --test src/lib/*.test.js
```

`cargo test` needs the placeholder sidecar first — see `docs/HANDOVER.md`.
